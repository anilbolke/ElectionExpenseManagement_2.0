🎯 WHAT THIS DOES:
──────────────────
After user scans QR code and pays:
1. User enters Transaction ID on website
2. System validates and saves payment details
3. Admin reviews and approves/rejects
4. User account/candidate activated automatically

═══════════════════════════════════════════════════════════════════

🚀 INSTALLATION (4 STEPS):

STEP 1: Run Database Script
────────────────────────────
mysql -u [username] -p [database] < database/qr_payments_table.sql

Or manually execute the SQL in database/qr_payments_table.sql


STEP 2: Compile & Deploy
─────────────────────────
If using Eclipse/IDE:
• Right-click project → Clean
• Right-click project → Build Project

OR restart Tomcat:
• Stop server
• Start server


STEP 3: Verify Servlet
───────────────────────
Check that servlet is mapped:
URL: /qrpayment
Class: com.election.servlet.QRPaymentServlet

(Already configured with @WebServlet annotation)


STEP 4: Test It
───────────────
1. Set payment mode to QR Code:
   UPDATE system_settings SET setting_value='qrcode' 
   WHERE setting_key='payment_mode';

2. Visit payment page as user
3. Enter transaction ID
4. Submit
5. Login as admin
6. Click "📱 Verify QR Payments"
7. Verify the payment

🔄 USER FLOW:
─────────────
1. User visits payment page (QR mode active)
2. Sees QR code image
3. Scans with UPI app (Google Pay, PhonePe, etc.)
4. Completes payment in UPI app
5. Returns to website
6. Enters Transaction ID (from UPI app)
7. Optionally uploads screenshot
8. Accepts terms & conditions
9. Clicks "Submit Transaction Details"
10. Sees message: "Payment pending verification"
11. Redirected to dashboard

═══════════════════════════════════════════════════════════════════

🔐 ADMIN FLOW:
──────────────
1. Admin logs in
2. Clicks "📱 Verify QR Payments" in navbar
3. Sees statistics:
   • Pending count
   • Verified count
   • Rejected count
4. Sees list of pending payments
5. For each payment:
   • View details
   • Verify (approve)
   • Reject (with reason)
6. On verification:
   • Payment marked verified
   • Candidate activated (if candidate payment)
   • User can access features

───────────────────────

• Required

• Alphanumeric

• Required
• Must be valid number

Terms:
• Must be accepted
• Timestamp recorded

🔍 DATABASE QUERIES:
────────────────────
View pending payments:
SELECT * FROM qr_payments WHERE payment_status = 'pending';

View all payments for a user:
SELECT * FROM qr_payments WHERE user_id = [USER_ID];

Check duplicate transaction:
SELECT * FROM qr_payments WHERE transaction_id = 'TRANS123';

Payment statistics:
SELECT payment_status, COUNT(*), SUM(amount) 
FROM qr_payments GROUP BY payment_status;

❗ IMPORTANT NOTES:
──────────────────
• Razorpay CANNOT verify transactions from other UPI apps
• Admin must manually check bank statement
• Each transaction ID can only be used once
• Payment activation is manual (admin approval required)
• Consider 24-48 hour SLA for verification

🐛 TROUBLESHOOTING:
───────────────────
Issue: Servlet not found
Solution: Check @WebServlet annotation, restart server

Issue: Table not found
Solution: Run database script again

Issue: Duplicate transaction error
Solution: Normal behavior - each ID can only be used once

Issue: Payment not saving
Solution: Check servlet logs, verify database connection
